Findings

Medium · Resolved — Donors have no sign-out control

The donor portal renders a persistent header, but the only actions in it are the REWEAR logo and a Home link. There is no way for a signed-in donor to end their session. Searching the whole application for a sign-out affordance returns exactly one implementation, and it lives in the admin shell:

  • app/admin/layout.tsx — has a working signOut({ redirectTo: "/login" }) server action.
  • app/donor/layout.tsx — nav items are Dashboard / My Donations / New Donation / Notifications, plus a Home link. No sign-out.
  • components/ — no sign-out component exists.

Impact: a donor on a shared or public device cannot log out; the session stays active until the cookie expires. This is also a privacy/accessibility gap for a platform that stores donor name, email, phone and pickup address.

Fix applied (see remediation log above): mirrored the admin pattern — a sign-out button in the donor header of app/donor/layout.tsx calling the same signOut() server action with redirectTo: "/login".

Info — Could not prove which commit the live bundle was built from

An initial attempt to fingerprint the deployment by probing for the locally-produced route chunk page-7331ef74aa9d375b.js returned 404, which looked like evidence the live bundle predated the local fix. That conclusion is not reliable — Next.js chunk filenames are not reproducible between a local build and a Vercel build. Proof: a shared runtime chunk that exists under the same name in both places has different contents (3,843 bytes locally vs 4,304 bytes on Vercel, different SHA-256).

What is solid: the live site already passes the wizard Review-step check, so the auto-submit behaviour is correct in production regardless. To confirm the deployed commit, check the Vercel dashboard — the deployment triggered by commit 52a4e4d (“bug fixed-7”) is the one that carries the wizard guard.

Low · Harness timing — First tracking lookup exceeded the wait window

The first /track?id=… navigation was given 2.5 s, which the cold server action exceeded. Re-running the identical URL twice, polling up to 15 s, found the donation both times (FOUND / FOUND), as did the ?don= variant. No application change is needed; treat this as a test-harness artefact.
